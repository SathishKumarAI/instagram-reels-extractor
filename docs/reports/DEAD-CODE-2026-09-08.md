# Dead-code audit — 2026-09-08

> A read-only pass over `src/reels_scrap/`, `app.py`, `scripts/`, `templates/` and `web/src/` for
> code that is defined and never used, fields that are written and never read, and config/doc
> entries that no longer point at anything. Produced by parsing every Python file with the stdlib
> `ast` module (not by grepping names), then confirming each candidate with an independent
> full-repo `git grep`. Nothing was edited.

## How this was determined

| Step | What it did | What it cannot see |
|---|---|---|
| **1. AST definition/reference index** | Parsed every tracked `.py` file (`src/`, `tests/`, `scripts/`, `app.py`) and recorded each `FunctionDef` / `ClassDef` / assignment as a definition, and each `Name(Load)`, `Attribute`, `ImportFrom` name, keyword-argument name and string literal as a reference. String literals count as references on purpose — a name reached by `getattr`, a dict key or a route string is **not** dead. | Names built by concatenation (`getattr(o, "pre" + x)`). None found in this repo. |
| **2. Attribute read/write split** | Re-walked every `ast.Attribute`, classifying `Store` vs `Load`, plus every `ast.keyword`, then joined that against the declared fields of `models.py`, `config.py` and `api/schemas.py`. This is the step that finds the `ocr_text` shape. | A field read only by `model_dump()` → JSON → a human eye. Called out per finding. |
| **3. Non-Python consumers** | Every candidate re-checked against `web/src/**` (`.ts`/`.tsx`), `templates/*.j2`, `*.yaml`, `*.md`. A pydantic field the React UI reads is not dead. | Nothing — this is a full-text sweep of the non-Python surface. |
| **4. Second, independent check** | Every entry below was re-run as a bare-name `git grep` over the whole tracked tree. A row appears here only when **AST said unreferenced AND `git grep` returned only the definition site**. Both checks were run for every row. | — |
| **5. Runtime confirmation** | `__all__` entries resolved by importing each module and testing `hasattr` — 0 stale. Config keys checked by walking each `config*.yaml` against the pydantic model tree — 0 unread keys. CLI flags collected from real `--help` output, not from source. Every `scripts/*.py` import of `reels_scrap.*` resolved — 0 broken. | — |
| **6. Cross-check with ruff** | `ruff check --select F401,F811,F841,ARG,ERA` over `src scripts app.py`. It independently reproduced every unused-parameter row below and found no unused import and no unused local. CI's own `ruff check src tests scripts` passes clean. | ruff does no cross-file reachability, which is why steps 1–4 exist. |

Excluded: `.venv/`, `.venv-win/`, `node_modules/`, `output/`, `data/`, `.git/`, `__pycache__/`.

## Limits of this audit

| This method cannot see | Consequence |
|---|---|
| Reachability from a *running* process | A function reached only by a name assembled at runtime would read as dead. None was found — every dynamic dispatch here (Typer, FastAPI, `ROUTERS`, jinja filters) uses a literal string, which step 1 counts as a reference. |
| Whether a live record's data is *useful* | `Reel.audio_path` and `Fact.frame` are dead **to code**. They are still bytes in every existing JSON record that a human can read. Deleting a pydantic field does not delete it from those records; `model_validate_json` ignores the extra key on load. |
| TypeScript reachability | `web/src` was swept full-text, not parsed. `tsconfig.json` sets `noUnusedLocals`/`noUnusedParameters` and CI runs `npx tsc -b`, so unused *locals* there are already impossible. Unused *exports* are covered by neither — of the 60 exported symbols in `web/src`, all 60 have a consumer; `backendChip` (`components/ModelBadge.tsx:7`) is exported but used only in its own file, which is a needless export, not dead code. |
| Anything untracked | The sweep covers `git ls-files` plus the working tree, minus the exclusion list. Files ignored by `.gitignore` (`data/`, `output/`, media) were not read. |
| Git history | "Was this ever used?" is not asked. A symbol dead today may be a rename away from a live caller on another branch. `deepseek` is checked out; `main` was not compared. |
| Semantic duplication | Two functions doing the same job under different names are both "referenced", so both look alive. `docs.py` vs `render/docs_site.py` were checked by hand and are genuinely different (consolidated HTML docs vs the mkdocs site). |
